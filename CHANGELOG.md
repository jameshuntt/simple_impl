# Changelog

## 0.1.11 (2026-10-19)

The toolkit: 100 `macro_rules!` helpers for the small bodies and one-line methods that are left when a derive doesn't fit. They come from an audit of the 49 public jameshuntt repositories, which found the same few shapes written out by hand over and over: one-expression methods (honest's Gf256, PETR's getters and predicates, recipe-session's id, name and version accessors, allot's RawBuf len, capacity and is_empty), consuming with_* setters in xccute_contract and ob-serve-a-bowl, guards at the top of a constructor that reject a zero size, an empty value or a duplicate (classified, allot, recipe_registry), and one-line trait impls (Default through new, From wrapping an error in a variant, PartialOrd through Ord). sc_*, builder_* and the derive didn't change; the toolkit sits beside them at the crate root.

## 0.1.10 (2026-10-15)

The derive feature now pulls simple_impl_derive 0.2.4, the collector release, where a broken struct gets every error in one compile. Nothing in src/, the README or the licenses changed, the work here is the proof around the derive. ui/ pins the exact compiler output for broken structs, and parity/ derives the same structs with 0.2.3 and 0.2.4 and checks they build the same commands, kitchen sink included. Neither one is published, so simple_impl still carries no test-only dependencies, and CI runs both before it publishes.
